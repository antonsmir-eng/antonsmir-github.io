## Серверный запуск

GitHub Pages публикует статические файлы и не выполняет API кабинета. Здесь используется Worker с SQLite D1 и объектным хранилищем R2. Для переноса на свой Cloudflare:

1. Установить зависимости из `pnpm-lock.yaml`: `pnpm install --frozen-lockfile`.
2. Создать отдельные D1 и R2, назначить привязки `DB` и `BUCKET` в собственной конфигурации Wrangler. `.openai/hosting.json` относится к существующему Site и не создаёт новый проект автоматически.
3. Применить миграции из `drizzle` к новой базе в порядке журнала. Перенос данных пользователей и файлов выполняется отдельно владельцем.
4. Настроить runtime-значения из `.dev.vars.example`. `ADMIN_BOOTSTRAP_HASH` — хеш, совместимый с `lib/cabinet-crypto.ts`; никаких секретов в GitHub не записывать.
5. Задать точный HTTPS-адрес сервера в `CABINET_ORIGIN`, собрать `pnpm build`, опубликовать Worker и привязки через официальный Wrangler.
6. Войти `admin` / `admin` при соответствующем начальном хеше, сменить пароль, заполнить реквизиты, пройти тестовый платёжный сценарий и затем настроить реальный магазин.

Ключи магазина, реквизиты и почтовый сервис не входят в исходники. Оплата картой по умолчанию выключена. Подробный путь клиента, роли, режимы оплаты и ограничения — `CABINET.md`. Официальное описание GitHub Pages: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages.
